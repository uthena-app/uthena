# 403 — Forbidden

## What this page does
Shown when a user is signed in but the role doesn't match what's required
to view a page. Distinct from 401 (logged out, redirect to /login) and
404 (route doesn't exist).

## Data this page shows
- The 403 status label
- A short explanation
- A "Go home" button + a "My account" link

## User actions
- Click "Go home" — navigates to `/`
- Click "My account" — navigates to `/account`
- Click the contact link — navigates to `/contact`

## What this page does NOT do
- It does NOT explain *why* the user is forbidden (no PII, no role info)
- It does NOT log the access (we don't have signal here; logs happen in
  the page that redirected)
- It does NOT offer a "request access" form (PH15 admin)

## Acceptance criteria
- [x] Page is a server component
- [x] 403 HTTP status is not required (this is a UI page, the redirect
      from the auth guard is the actual signal)
- [x] Skip-to-content link still works
- [x] Keyboard accessible
- [x] No PII in the page

## Design reference
Empty-state pattern from the design system.

## Security
- Public route (the auth guard at the calling site is what enforces the
  403; the page itself shows for any visitor who lands here)

## Performance
Static page, prerendered at build time. p95 < 50ms.

## Out of scope for v1
- Per-resource "request access" form
- Showing the user's role
- Logging the 403 event

## Open questions for human
None.
