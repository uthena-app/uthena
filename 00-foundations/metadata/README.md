# `00-foundations/metadata` — Page metadata helper

## What this is

A single source of truth for Next.js `Metadata` exports across
every page in the app. Two functions:

- **`buildPageMetadata({ title, description, path, image?, type?, noindex?, locale?, publishedTime?, modifiedTime? })`**
  — emits the full `Metadata` shape including `alternates.canonical`,
  `openGraph`, `twitter`, and (when `noindex: true`) `robots`.

- **`sensitivePageMetadata({ title, description, path })`** —
  thin wrapper around `buildPageMetadata` with `noindex: true`.
  Use for cart, checkout, login, signup, password reset, email
  verify, account, partner, admin, and any future authenticated
  surface.

Plus five constants:

- `SITE_NAME` (`'Uthena'`) — `og:site_name` + default Twitter title suffix.
- `SITE_ORIGIN` (`'https://uthena.com'`) — joins with `path` for
  canonical URLs.
- `SITE_LOCALE` (`'en_US'`) — default OG locale.
- `OG_IMAGE_GENERATOR_PATH` (`'/og'`) — the dynamic image route.
- `DEFAULT_OG_IMAGE` (`'/og?title=Uthena&subtitle=Wholesale+PLR+Video+Courses'`)
  — the site-wide default OG image.

## Why a helper

Hand-rolling `Metadata` exports for 30+ pages is bug bait. Easy
to forget `url`, `siteName`, `type`, the Twitter Card counterpart.
The helper:

1. Forces every page to emit a canonical URL (relative path →
   absolute `https://uthena.com/...`).
2. Forces every page to emit a complete OpenGraph block
   (`type`, `siteName`, `title`, `description`, `url`, `locale`,
   `images` with `width` + `height` + `alt`).
3. Forces every page to emit a complete Twitter Card block
   (`card: 'summary_large_image'`, `title`, `description`, `images`).
4. Falls back to a dynamic OG image so even pages without their
   own image get a branded share card.

When we add a new field (e.g. a Twitter handle in P19.16), it's
a one-line edit here.

## When to use

| Page surface | Use |
|---|---|
| Public marketing pages (home, browse, bundles, collections, search, newsletter, contact, FAQ, legal pages) | `buildPageMetadata` (default — indexable) |
| Product detail | `buildPageMetadata` with `image: product.thumbnail_url` (so the OG image is the product cover, not the generic brand card) |
| Cart, checkout, success, canceled | `sensitivePageMetadata` |
| Login, signup, reset-password, update-password, verify-email | `sensitivePageMetadata` |
| Library, account, account/* | `sensitivePageMetadata` |
| Partner/*, admin/* | `sensitivePageMetadata` (or `noindex: true` on the layout if multiple pages share it) |
| 404 / not-found | `sensitivePageMetadata` with `noindex: true` + the standard 404 copy |

## Dynamic OG image generator

The default OG image is generated by `app/og/route.tsx` using
Next.js's built-in `next/og` package (no extra dependency —
it's part of `next@15.0.3`). It accepts `?title=` and
`?subtitle=` query params and returns a 1200×630 PNG with the
Uthena brand chrome (dark canvas + teal accent + Inter Tight
title + small "uthena.com" footer).

Pages can override the image by passing `image: <url>` to the
helper. Product pages do this with `product.thumbnail_url` so
shares show the course cover instead of the brand-default card.

## Notes

- The canonical URL is hardcoded to `https://uthena.com` — that's
  the production origin. Dev previews (`localhost:3100`) use a
  different origin and don't need production canonicals.
- For Twitter, we set `card: 'summary_large_image'` because larger
  cards get more click-through on cold shares. We don't set
  `twitter.site` (no Twitter handle is defined yet — see P19.16).
- The `images` array always carries `width: 1200` + `height: 630` +
  `alt: title` — that's the standard social-share card spec and
  what crawlers expect for `og:image`.
