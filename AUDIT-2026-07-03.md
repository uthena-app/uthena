# Uthena — Full Production-Readiness Audit

**Date:** 2026-07-03 · **Scope:** Security · Design/UI/UX · Structure & Code Quality · Speed & Smartness · **Method:** four parallel read-only audits of the full tree, cross-checked against the brand contract (`docs/BRAND_AND_POSITIONING.md`) and the **ponytail** engineering rule (smallest change that works, deletion over addition).

**Companion docs:** [`TODO-HARDENING.md`](./TODO-HARDENING.md) — the actionable backlog for a Sonnet agent · [`DECISIONS-NEEDED.md`](./DECISIONS-NEEDED.md) — what needs your input.

---

## Verdict

The build is **well above average for a pre-launch marketplace** — strict TypeScript that actually passes, real layering discipline, a genuinely good design system, ~4,600 tests including failure-path coverage. It is **not yet production-ready**, and the gaps are concentrated, not spread thin:

- **One launch-blocking security hole:** any registered user can self-promote to admin (RLS gates the row, not the `role` column).
- **The "AI-built" feel was mostly one bug:** the brand fonts were never loaded, so the whole app rendered in system fonts. That plus placeholder hero art and ~⅓ of surfaces using invented CSS token names that silently fall back to nothing. The design *system* is good; the *implementation* drifted from it.
- **Operational gaps, not structural ones:** no git, a red test suite (trivially fixable causes), three money-affecting payment-webhook stubs, and ~103MB of deletable clutter.

Nothing here suggests a rewrite. It's a hardening pass.

## Findings by area

### Security
**Critical:** SEC-1 — RLS `profiles_self_update` gates the row but not the `role` column, so a customer can `update({role:'admin'})` from the browser and unlock every admin policy. **This blocks launch.** (~15-line trigger migration.)
**High:** maintenance-mode driven by an unsigned, client-forgeable cookie (SEC-2); no durable rate limiting on public write endpoints, 8 per-instance `Map` limiters (SEC-3).
**Medium:** CSP allows `'unsafe-inline'` scripts, no nonces (SEC-4); Bunny webhook accepts either secret on either surface (SEC-5).
**Done well (don't break):** the open-redirect defense (`safeNext()`) is thorough and used on every auth flow; the Stripe webhook is textbook (signature → idempotency claim → dispatch → release-on-transient-failure); file-vault access control closes IDOR consistently (session → ownership RPC → signed URL → append-only audit).

### Design / UI / UX
**High:** token-vocabulary drift — ~40 phantom tokens across hundreds of usages, 43 with no fallback (e.g. `border-radius: var(--radius-md)` → 0); admin pages render black-on-black; hero is placeholder gradients.
**Medium:** five competing button systems; ~30 files styled entirely inline; cart/checkout prices not in mono (brand requires it); the two designed "temperature" flourishes (tri-color pip, section tints) are dead code; auth card off the scale with no logo.
**Done well:** `ProductCard` + browse sidebar are token- and mockup-faithful with correct two-signal semantics; the accessibility infrastructure (skip link, focus-visible rings, forced-colors + reduced-motion, focus-trap hooks) is better than most agency work; header/footer and brand voice are clean (zero emoji, zero exclamation marks, no lorem).

### Structure & Code Quality
**Critical/Decision:** no git repo (13 `.bak` files as manual version control).
**High:** ~103MB deletable clutter; `STUBS.md` at 393KB is unmanageable (duplicate ID STUB-122, no severity field); production-blocking payment stubs (STUB-061/062/063/006/052).
**Medium:** `next@15.0.3` (CVE-2025-29927) + `react@19-RC`/`@types/react@18` mismatch; `rateLimitVerdict` duplicated 8×; one foundations→features layer inversion; migration `0005b` naming (the last red test).
**Done well:** the strictest practical tsconfig (`exactOptionalPropertyTypes` + `noUncheckedIndexedAccess`) with a clean `tsc --noEmit`; real layering discipline (500+ `app/` imports, effectively one violation, zero SDK leakage into routes); a failure-path test culture that even pins known-bad behavior with tests.

### Speed & Smartness
**High:** ISR is dead — cookie/header reads in the root layout make every route dynamic despite `revalidate` everywhere; `next/image` is used nowhere, so full-size Bunny originals ship on every card.
**Medium (all quick):** double-fetch on detail pages (wrap 3 queries in `cache()`); dynamic sitemaps; `getActiveCategories` counts all products in JS; no LCP prioritization; posthog-js eager in every bundle pre-consent.
**Done well:** the edge middleware is lean (no DB at the edge); `Promise.all` and paginated admin lists throughout; RSC-first islands with 61 `loading.tsx` files and server-rendered TipTap (the editor never ships to readers).
